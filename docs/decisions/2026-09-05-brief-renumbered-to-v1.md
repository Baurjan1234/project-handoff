# Brief renumbered to repo v1

**Decision.** The project brief enters the repo as `docs/project-brief-v1.md`. Version
numbers restart at 1 on the day the hackathon starts.

**Why.** The three pre-hackathon drafts were idea iterations before any code existed.
Carrying "v3" into the repo makes the first build-week edit v4 and hides which changes
were made under the actual constraints of the build. From here a version bump means
something changed while code was being written.

**Consequences.** The document's content is the final pre-hackathon draft, unchanged.
Its provenance block records the earlier drafts and what the round-2 audits changed, so
nothing is lost. CLAUDE.md points at this path.
